Public repositoryMachine facts
What is Sley?

Sley is an agent-native structural programming language for compiler-mediated, human-reviewed software change. It is designed so readable source remains central while compiler-exposed structure supports bounded inspection, planning, authority checks, and verification.

What problem does structural programming solve?

It reduces how much intent has to be reconstructed around a code change. Program shape, candidate deltas, diagnostics, authority, and proof can become explicit workflow surfaces instead of remaining scattered across prompts, tickets, and memory.

How does Sley support human code review?

Human review is part of the design. Sley makes a proposed change easier to inspect by carrying structure, intent, and evidence into the review projection.

Is Sley open source?

Yes. The public repository is available under Apache-2.0 as a self-hosted structural programming language with a passing local v1 gate and a machine-checked evidence surface.

What does the current public checkpoint prove?

The current surface includes the self-hosted Sley compiler, runnable language and report workflows, structural inspection, planned-change and dry-run paths, diagnostics, verification artifacts, a bounded read-only tool bridge, a staged-change guard, and report-only structural comparison. See the repository README for the builder-facing entry point.

Is Sley self-hosted?

Yes. Sley's parser, checker, runtime, bootstrap, and report semantics are owned by Sley source and exercised through its verification surface. The public command layer exposes the compiler through structural inspection, diagnostics, planning, and evidence workflows.

How do Sley authority gates work?

A deterministic gate reports an explicit authority state. Host, provider, financial, deployment, publishing, and other consequential actions follow the authority defined by the surrounding operator workflow.

How is the current evidence published?

The public branch carries 42 report schemas, 128 contract fixtures, 66 accepted and rejected corpus cases, 199 integration checks, and a 23 of 23 local v1 gate result at the 2026-08-22 checkpoint. It also publishes a current evidence packet, a language specification, and a contract reference.

How can I evaluate Sley today?

Start with the public repository, run the local v1 proof gate, explore the structural command surfaces, and review the schema, contract, corpus, and integration evidence. The Apache-2.0 branch is built for direct technical evaluation and contribution.

Who builds Sley?

Sley is developed by Greyforge Labs. The canonical public product site is sleylang.org, and the public source lives in the GreyforgeLabs/sley repository.

How should Sley be cited?

Use the concise product description on this site and pair stronger category or historical claims with the repository's current evidence, language specification, contract reference, and primary-source comparison packet.
