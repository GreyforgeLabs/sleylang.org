This walkthrough is a public-safe walkthrough designed to show direction and behavior without exposing all internal internals.

1. Start from readable source

Load a source project and confirm the review view is clear. Sley assumes humans remain the final context owner for intent and approvals.

2. Inspect bounded structure

Ask for structural context first: declarations, dependencies, and recent task calls. Do not begin by rewriting full files.

3. Prepare diagnostics

Read diagnostics and diagnostics-driven hints. Use the warning surfaces to shrink the working area before edit planning.

4. Draft a narrow planned edit

Keep edits scoped to one bounded intent. Token-efficient sessions should minimize context width, so each change should have one clear purpose.

5. Validate authority and proofs

If runtime capabilities are involved, ensure required explicit gates are satisfied before accepting any mutation.

6. Accept and hand off

Accept only when checks are clean, provenance is preserved, and the change is traceable through explicit evidence artifacts.

7. Copyable reference
