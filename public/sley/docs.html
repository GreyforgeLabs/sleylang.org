Sley / Technical brief

Public architecture and proof posture

Structure for software change.

Sley is an agent-native structural programming language designed to make software intent legible to tools, bounded by compiler checks, and reviewable by the people responsible for the result.

Thesis

Programming surfaces should carry more of the change contract.

Most software workflows separate code from the context needed to change it safely. Intent lives in tickets, prompts, review comments, runbooks, and memory. An autonomous workflow has to reconstruct that context before it can make a useful edit.

Sley approaches the problem at the language and compiler boundary. Human-readable source remains the review projection. Compiler-exposed structure becomes the intended work surface for inspection, planning, validation, and evidence-aware handoff.

Public description

Sley is a self-hosted, agent-native structural programming language for compiler-mediated, human-reviewed software change.

Design principles

Make the important parts explicit.

Human-readable by design

Source remains understandable to the people who own the software and its consequences.

Structural for tools

Compiler surfaces expose program shape and relationships without depending on repeated prose reconstruction.

Bounded before mutation

Candidate changes can be inspected, checked, and narrowed before the workflow accepts a write.

Evidence in the handoff

Verification and provenance travel with accepted work instead of becoming an afterthought.

Change model

One lifecycle, four questions.

  1. 01

    Inspect

    What structure, relationship, diagnostic, or risk surface matters to the requested change?

  2. 02

    Plan

    What narrow transformation is being proposed, and what stays outside its scope?

  3. 03

    Gate

    Does the proposed effect fit the declared authority and the operator's review boundary?

  4. 04

    Verify

    What artifacts show that the accepted result is coherent and ready for handoff?

Authority posture

Capability and permission stay explicit.

Sley represents the ability to describe or inspect an effect separately from authority to carry it out. A deterministic gate reports the declared authority state while the surrounding operator workflow governs host, provider, financial, deployment, and publishing actions.

This separation is central to the product direction: agents reason over more structure while operators retain clear control over consequential effects.

Self-hosted architecture

Sley owns the semantics that define Sley.

The self-hosted Sley compiler carries parser, checker, runtime, and report semantics in Sley source. The public command layer turns that language-owned structure into practical inspection, planning, verification, and developer workflows.

The result is a language whose implementation matches its product thesis: structure is explicit, evidence is inspectable, and autonomy stays reviewable.
