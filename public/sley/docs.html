1. Thesis

Sley is designed for the programming workflow that coding agents actually need: the language AI agents want to speak. It is designed by AI for AI to reduce token churn through compact source, typed structure for tools, deterministic authority checks, compiler-rejected illegal edits, and evidence after accepted change.

The bootstrap implementation is deliberately strict. Its job is to teach the language in context, expose bounded structure, reject unsafe assumptions, and keep the human-readable projection coherent while preserving token-efficient, AI-optimized workflows.

2. Public System Model

LayerPublic Description
Source projectionThe readable file form humans review. It is not the only surface agents should rely on.

Evidence surfaceProvenance, verification, package, and handoff artifacts for accepted changes when review history matters.

3. Current Internal Breadth

The v1.0 tree moves beyond a tiny parser demo. It now includes a compiler/runtime slice, project form, structural inspection, lint and readiness reporting, planned change previews, authority gates, local package evidence, trace and seal artifacts, and a handoff path toward ZJX.

Language Surface

Modules, declarations, task boundaries, typed values, explicit authority, structured expressions, and controlled mutation are part of the current internal work.

Tool Surface

Agents can use compiler-produced structural, diagnostic, query, hygiene, planning, and verification reports inside the workflow toolchain.

Evidence Surface

Contract fixtures, smoke manifests, schema snapshots, local CI helpers, and validation helpers support public release readiness and compatibility checks.

5. Authority Model

Sley treats external authority as a first-class language concern. File access, data access, network text, shell output, model completion, secrets, deploy-like actions, and spend-like actions are not hidden incidental side effects in the public design story.

In public v1.0, these paths are deterministic gates and explicit policy boundaries. They do not execute implicit live shell commands, model-provider calls, secret reads, money movement, market orders, deployment actions, or uncontrolled network operations.

6. Agent Workflow

  1. Read the compact project context and current compiler reports.
  2. Inspect the relevant bounded structural surface instead of loading the whole project as raw text.
  3. Use diagnostics and hygiene reports to understand what is wrong or risky.
  4. Generate a narrow candidate change through the compiler-mediated edit layer.
  5. Preview the change without mutation and let the compiler reject illegal structure.
  6. Run strict checks and deterministic gates before acceptance.
  7. Leave provenance, verification, and handoff artifacts when the change is accepted.

7. What Is Deliberately Missing

The public site does not include a starter program, command transcript, payload example, operation catalog, schema root inventory, grammar section, parser rule, type-checking algorithm, graph format, module resolution recipe, fixture corpus, or self-hosting design map.

Those details are useful to users after source release. Before release, they are also useful to anyone trying to reproduce the language from the outside.

8. Current Limits

  • Sley is released as v1.0 and continues active hardening after release.
  • The public site is a release brief and project entrypoint, not a full API reference.
  • Some internal details remain intentionally undisclosed for security and long-tail release planning reasons.

9. Release Direction

Sley v1.0 now links open-source source, release artifacts, and contribution paths. The next public hardening pass will expand runnable examples, contribution playbooks, and release-grade verification examples.
